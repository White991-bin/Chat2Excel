## 文件子服务实现

### 1. 文件子服务介绍

chat2Data项目支持以自然语言方式操作Excel文件 和 数据库，数据库支持MySQL数据库和SQLite数据库。文件子服务主要负责文件操作相关请求的处理，比如上传文件、下载文件、删除文件、获取文件列表等。

#### 1.1 自然语言操作Excel文件

在智能Excel页面中，通过自然语言操作Excel文件流程如下：
- 在智能Exce页面中，用户先选择好模型，然后点击新建会话按钮创建新会话后才能上传Excel文件，Excel文件仅支持xlsx格式文件(因为后端使用OpenXLSX库解析Excel文件，该库目前仅支持xlsx格式文件)
- 网关收到上传Excel文件请求，对该请求进行鉴权后，将上传Excel文件请求路由至文件子服务
- **文件子服务收到Excel文件上传请求后：**
    - **将Excel文件上传至FastDFS**
    - **并在本地保存一份Excel文件(在本地保存时会按照用户昵称隔离)**
    - **通过Excel解析子服务对Excel文件进行解析，解析出Excel文件的worksheet表列表，以及各个worksheet的表数据**
    - **通过存储子服务将Excel文件解析结果存到MySQL数据库**
    - **删除本地保存的Excel文件**
    - **组织响应返回给网关**
- 网关收到RPC响应后，将RPC响应转换为HTTP响应，最后返回给前端进行渲染
- 文件上传成功后，前端会主动发送Excel文件预览请求，网关将请求路由至文件子服务，文件子服务通过存储子服务获取Excel文件的worksheet表数据并返回给网关，网关再将数据转换为HTTP响应，最后返回给前端进行渲染
- 之后，用户就可以在前端页面发送消息，通过自然语言方式操作Excel文件。注意：通过自然语言操作Excel文件逻辑由AI子服务实现

#### 1.2 自然语言操作数据库

chat2Data将来支持通过自然语言操作MySQL和SQLite数据库。在智能DB页面中，通过自然语言操作SQLite数据库流程如下：
- 用户上传SQLite文件，SQLite文件后缀为.db格式
- 网关收到上传SQLite文件请求，对该请求进行鉴权后，将上传SQLite文件请求路由至文件子服务
- **文件子服务收到SQLite文件上传请求后，将SQLite文件上传至FastDFS，然后将RPC结果返回给网关**
- 网关收到RPC响应后，将RPC响应转换为HTTP响应，最后返回给前端进行渲染
- 前端发起数据库连接请求，数据库子服务会通过文件子服务下载SQLite文件，拿到SQLite文件路径后，数据库子服务再连接SQLite数据库，获取数据库中表列表以及表数据返回给前端渲染
- 之后，用户就可以在前端页面发送消息，通过自然语言操作数据库。注意：通过自然语言操作数据库逻辑由AI子服务实现

注意：
- 文件子服务在收到上传Excel文件 和 上传SQLite文件请求后，后续的处理逻辑不同，因此分两个RPC接口处理
- 在上传Excel文件前，前端页面需要先创建聊天会话，聊天会话创建成功后才能上传Excel文件
- 等Excel文件上传成功后，前端会主动发送将Excel文件关联到聊天会话的请求，这样才能知道某个聊天会话对应哪个Excel文件
- 在前端页面展示用户上传的文件列表时，文件列表上需要显示文件名称、文件大小、文件上传时间等信息，因此上传文件时，需要先上传文件元数据后上传文件内容
- 将来文件子服务和存储子服务运行在同一个宿主机的不同容器中，在docker-compose中配置好volume挂载，因此文件子服务将文件保存在本地后，Excel解析子服务和数据库子服务都可以直接访问到文件内容
- 前端文件路径为/home/dev/workspace/chat2data-tech/chat2data-tech/chat2Data/svc_gatewayService/build/www，你可以熟悉下前端代码，了解文件上传前后的处理逻辑

  - 上传文件
  - 下载文件
  - 删除文件
  - 预览文件(Excel文件)
  - 获取文件列表
  - 关联文件和聊天会话
  - 上传SQLite文件
  - 获取SQLite文件

### 3. 数据库设计

#### 3.1 文件信息表

前端页面显示用户文件列表时，需显示文件名称、大小、上传时间等信息，因此需要对文件信息进行持久化存储，文件信息表设计如下：
| 字段名称 | 字段类型 | 约束 | 空值 | 备注 |
| --- | --- | --- | --- | --- |
| id | BIGINT UNSIGNED | PRI | NOT NULL | 主键，自增ID |
| 文件ID | VARCHAR(32) | URI | NOT NULL |  文件ID，唯一标识一个文件 |
| 文件大小 | BIGINT UNSIGNED |  | NOT NULL |  |
| 文件上传时间 | BIGINT UNSIGNED |  | NOT NULL |  |
| 文件名称 | VARCHAR(64) |  | NOT NULL |  |
| 文件后缀 | VARCHAR(8) |  | NOT NULL |  |
| 文件在fastDFS中Id | VARCHAR(64) |  | NOT NULL |  通过该ID在FastDFS中进行文件下载、删除等操作|
| 用户Id | VARCHAR(32) |  | NOT NULL | 文件在本地存储时需按照用户隔离 |
| 聊天会话ID | VARCHAR(32) |  | NOT NULL | Excel文件需关联聊天会话ID，SQLite文件无需关联 |

**注意**
- 因为经常需要通过文件Id获取该文件的信息，所以需要在该表中添加文件Id的索引
- 数据库表名tbl_fileInfo
- 创建表的SQL语句，将来需要通过odb映射文件生成
- 假设文件子服务可执行程序在build目录，文件在本地存储时路劲为build/files/will/xxx.xlsx，其中will为useId用户的用户昵称

#### 3.2 worksheet与数据库表映射表

Excel文件解析之后，需要将worksheet的表数据存储到数据库中，每个worksheet对应一张数据库表。
为了方便获取每个Excel文件对应哪些worksheet，每个worksheet在数据库中对应哪张表，需要维护一份worksheet到数据库表的映射关系表。该表设计如下：

| 字段名称 | 字段类型 | 约束 | 空值 | 备注 |
| --- | --- | --- | --- | --- |
| id | BIGINT UNSIGNED | PRI | NOT NULL | 主键，自增ID |
| 文件Id | VARCHAR(32) | FK + CASCADE | NOT NULL | 外键+级联删除|
| worksheet名称 | VARCHAR(32) |  | NOT NULL |  |
| 数据库表名 | VARCHAR(64) |  | NOT NULL |  |

**注意**
- 因为经常需要通过文件Id获取该文件的所有worksheet，所以需要在该表中添加文件Id的索引
- 数据库表名tbl_worksheet
- 文件删除后，需要级联删除该表中的所有记录
- 创建表的SQL语句，将来需要通过odb映射文件生成

### 4. 缓存设计

#### 4.1 文件元数据缓存

过期时间：3天，与会话id保持一致
缓存策略：
- 写策略：写DB成功后，再删除Redis。
- 读策略：Cache-Aside。先查redis，未命中再查DB，查到后回填Redis。
- 删除/失效策略：先删除MySQL，再删除Redis，或者TTL到期后自动删除。
缓存类型：hash
key：file:fileId
value：
  - 文件Id
  - 文件名称
  - 文件大小
  - 上传时间
  - 文件后缀
  - 存储路径
  - 文件状态
  - 用户Id
  - 聊天会话Id
value最终会被组织称Json结构进行缓存。

#### 4.2 worksheet与数据库表映射缓存

过期时间：3天，与会话id保持一致
缓存策略：
- 写策略：写DB成功后，删除Redis。
- 读策略：Cache-Aside。先查redis，未命中再查DB，查到后回填Redis。
- 删除/失效策略：先删除MySQL，再删除Redis，或者TTL到期后自动删除。
缓存类型：hash
key：worksheet:fileId
value：
  - 文件Id
  - < worksheet, DB数据表 >集合
value最终会被组织称Json结构进行缓存。

### 6. RPC服务器搭建
RPC服务器搭建由FileServer类实现，该类内部包含：
- 服务注册对象指针：用于注册服务到注册中心。
- 服务发现对象指针：用于发现其他服务。
- brpc服务器对象指针：用于启动RPC服务器。
- rpc接口类对象指针：用于实现RPC接口。

RPC服务器实例创建、注册中心实例创建、服务发现实例创建、文件业务层以及接口层实例创建，由FileServerBuilder类完成。
FileServerBuilder类通过建造者模式，完成RPC服务器端口、注册中心结构、MySQL连接、Redis连接、ETCD服务器地址、FastDFS客户端等初始化，最后通过build构造好各个对象并返回RPC服务器实例。
