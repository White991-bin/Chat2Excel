## 通知子服务实现

### 1. 通知子服务介绍

通知子服务属于内部服务，不和网关进行交互，主要负责发送验证码和普通邮件。
前端发送获取验证码请求后，网关将获取验证码请求路由给用户子服务，用户子服务生成验证码之后，通过通知子服务将验证码发送到用户邮箱。
前端发送普通邮件请求后，网关将普通邮件请求路由给AI子服务，AI子服务生成普通邮件内容之后，通过通知子服务将普通邮件发送到用户邮箱。

### 2. 接口定义

通知子服务总共涉及到2个RPC接口，分别是：
- 发送验证码
- 发送普通邮件

具体的RPC接口定义如下：
```proto

syntax = "proto3";
package chat2Data.notifyService;
option cc_generic_services = true;

// 通知服务接口定义
//////////////////////// 发送验证码 ////////////////////////
message SendVerifyCodeRequest {
  string request_id = 1;    // 请求id
  string email = 2;         // 收件人邮箱
  string code = 3;          // 验证码
}

message SendVerifyCodeResponse {
  string request_id = 1;     // 请求id
  int32 error_code = 2;      // 错误码
  string error_msg = 3;      // 错误描述符
}

//////////////////////// 发送邮件 (普通邮件) ////////////////////////
message SendEmailRequest {
  string request_id = 1;     // 请求id
  string to_email = 2;       // 收件人邮箱
  string subject = 3;        // 邮件主题
  string content = 4;        // 邮件内容（HTML格式）
}

message SendEmailResponse {
  string request_id = 1;     // 请求id
  int32 error_code = 2;      // 错误码
  string error_msg = 3;      // 错误描述符
}

// 通知服务RPC定义
service NotifyService {
  // 发送验证码邮件
  rpc SendVerifyCode(SendVerifyCodeRequest) returns (SendVerifyCodeResponse);
  // 发送普通本邮件
  rpc SendEmail(SendEmailRequest) returns (SendEmailResponse);
}

```
### 3. 封装邮件发送客户端
邮件发送客户端使用libcurl封装，具体参考/home/dev/workspace/chat2data-tech/libSource/cpp-microservice-scaffold/source/mail.h 和 mail.cc 的实现。

需要封装类：
- EmailSender：抽象基类，使用curl封装发送邮件的主体流程以及回调函数，邮件正文构造通过纯虚函数方式由具体子类实现。邮件正文构造包含邮件主题、邮件内容（HTML格式）。
- VerifyCodeEmailSender：继承EmailSender，负责发送验证码邮件的子类，实现验证码邮件的正文构造。
- NormalEmailSender：继承EmailSender，负责发送普通邮件的子类，实现普通邮件的正文构造。

### 4. 异步支持
由于发送邮件比较耗时，邮件发送采用异步方式处理。
每个发送邮件的请求，都转换成一个邮件任务EmailTask，放在队列中，然后由专门的线程持续从队列获取EmailTask并发送，避免主线程卡顿。
异步支持通过EmailWorker类实现，该类包含：
- 启动邮件发送线程
- 停止邮件发送线程
- 添加发送邮件任务到队列
- 由工作线程循环从队列获取EmailTask并发送
注意：实现时需要考虑线程安全和同步问题，队列操作需要加锁保护，避免多个线程同时操作队列导致的不一致状态。
EmailTask结构需要包含：
- 接收者邮箱
- 邮件主题
- 邮件正文
- 邮件发送器指针：用于调用具体的邮件发送子类

### 5. 邮件发送业务逻辑实现
发送邮件的具体业务逻辑主要由NotifyBusiness类完成，该类是对EmailSender和EmailWorker的封装，主要负责curl的全局初始化以及资源清理，并处理发送邮件的业务逻辑。
向外暴露的接口包括：
- 启动邮件发送线程
- 停止邮件发送线程
- 发送验证码邮件：构造验证码邮件任务EmailTask并添加到队列
- 发送普通邮件：构造普通邮件任务EmailTask并添加到队列

### 7. RPC服务器搭建
RPC服务器搭建由NotifyServer类实现，该类内部包含：
- 服务注册对象指针：用于注册服务到注册中心。
- brpc服务器对象指针：用于启动RPC服务器。
- rpc接口类对象指针：用于实现RPC接口。

RPC服务器对象创建、注册中心对象创建、邮件客户端结构初始化由NotifyServerBuilder类完成。
NotifyServerBuilder类通过建造者模式，完成RPC服务器端口、注册中心结构初始化、邮件客户端结构初始化，最后通过build构造好各个对象并返回RPC服务器对象。

具体实现参考：chat2data-tech/chat2Data/svc_userService/userServer.h 、userServer.cc 、 userServerBuilder.h 、userServerBuilder.cc 的实现
注意：NotifyServer类 和 NotifyServerBuilder类放在一个.h 和 .cc文件中实现。

### 9. 实现流程

1. 熟悉bite_scaffold中邮件发送封装代码，实现邮件通知子服务的邮件发送客户端：
    - 封装EmailSender类，使用curl封装发送邮件的逻辑，头文件为emailSender.h，源文件为emailSender.cc，包含在notifyService命名空间中。
    - 封装VerifyCodeEmailSender类，负责发送验证码邮件的子类，实现验证码邮件的正文构造，头文件为verifyCodeEmailSender.h，源文件为verifyCodeEmailSender.cc，包含在notifyService命名空间中。
