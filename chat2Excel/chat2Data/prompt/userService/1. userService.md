## 用户子服务

### 1. 用户子服务介绍

用户子服务负责处理用户相关的业务逻辑，包括用户注册、登录、获取个人信息等，以RPC方式给网关提供服务。除此之外，还需要提供服务注册和服务发现功能，确保服务之间的通信正常。


### 2. 接口定义

用户子服务总共涉及到9个RPC接口，分别是：
- 检测用户昵称是否唯一 
- 检测用户邮箱是否唯一
- 用户注册
- 密码登录
- 获取验证码
- 邮箱登录
- 会话登录
- 退出登录
- 获取用户信息

具体的RPC接口定义如下：
```proto

syntax = "proto3";   // 指定使用 proto3 语法版本
package chat2Data.userService;  // 定义包名，类似于C++中的命名空间
option cc_generic_services = true;   // 生成 RPC 服务类

// 用户服务接口定义
//////////////////////// 检测昵称是否唯一 ////////////////////////
message ValidNicknameRequest {
    string request_id = 1;       // 请求id
    string nickname = 2;         // 昵称
}

message ValidNicknameResponse {
    string request_id = 1;       // 请求id
    int32 error_code = 2;        // 错误码
    string error_msg = 3;        // 错误信息
}

//////////////////////// 检测邮箱是否唯一 ////////////////////////
message ValidEmailRequest {
    string request_id = 1;       // 请求id
    string email = 2;            // 邮箱
}

message ValidEmailResponse {
    string request_id = 1;       // 请求id
    int32 error_code = 2;        // 错误码
    string error_msg = 3;        // 错误信息
}

//////////////////////// 用户注册 ////////////////////////
message UserRegisterRequest {
    string request_id = 1;       // 请求id
    string nickname = 2;         // 昵称
    string password = 3;         // 密码
    string email = 4;            // 邮箱
}

message UserRegisterResponse {
    string request_id = 1;       // 请求id
    int32 error_code = 2;        // 错误码
    string error_msg = 3;        // 错误信息
}

//////////////////////// 会话登录 ////////////////////////
message SessionLoginRequest {
    string request_id = 1;       // 请求id
    string session_id = 2;       // 会话id
}

message SessionLoginResponse {
    string request_id = 1;       // 请求id
    int32 error_code = 2;        // 错误码
    string error_msg = 3;        // 错误信息
}

//////////////////////// 密码登录 ////////////////////////
message PasswdLoginRequest {
    string request_id = 1;       // 请求id
    string username = 2;         // 用户名（邮箱或昵称）
    string password = 3;         // 密码
}

message PasswdLoginResult {
    string session_id = 1;       // 会话id
}

message PasswdLoginResponse {
    string request_id = 1;       // 请求id
    int32 error_code = 2;        // 错误码
    string error_msg = 3;        // 错误信息
    PasswdLoginResult result = 4;// 登录结果
}

//////////////////////// 获取验证码 ////////////////////////
message GetCodeRequest {
    string request_id = 1;       // 请求id
    string email = 2;            // 邮箱
}

message GetCodeResult {
    string code_id = 1;          // 验证码id
}

message GetCodeResponse {
    string request_id = 1;       // 请求id
    int32 error_code = 2;        // 错误码
    string error_msg = 3;        // 错误信息
    GetCodeResult result = 4;    // 获取验证码结果
}

//////////////////////// 邮箱验证码登录 ////////////////////////
message VcodeLoginRequest {
    string request_id = 1;       // 请求id
    string email = 2;            // 邮箱
    string verify_code = 3;      // 验证码
    string code_id = 4;          // 验证码id
}

message VcodeLoginResult {
    string session_id = 1;       // 会话id
}

message VcodeLoginResponse {
    string request_id = 1;       // 请求id
    int32 error_code = 2;        // 错误码
    string error_msg = 3;        // 错误信息
    VcodeLoginResult result = 4; // 登录结果
}

//////////////////////// 退出登录 ////////////////////////
message LogoutRequest {
    string request_id = 1;       // 请求id
    string session_id = 2;       // 会话id
}

message LogoutResponse {
    string request_id = 1;       // 请求id
    int32 error_code = 2;        // 错误码
    string error_msg = 3;        // 错误信息
}

//////////////////////// 获取用户信息 ////////////////////////
message GetUserInfoRequest {
    string request_id = 1;       // 请求id
    string session_id = 2;       // 会话id
    string user_id = 3;          // 用户id
}

// 用户信息
message UserInfo {
    string user_id = 1;     // 用户id
    string nickname = 2;    // 昵称
    string email = 3;       // 邮箱
}

message GetUserInfoResult {
    UserInfo user_info = 1;     // 用户信息
}

message GetUserInfoResponse {
    string request_id = 1;       // 请求id
    int32 error_code = 2;        // 错误码
    string error_msg = 3;        // 错误信息
    GetUserInfoResult result = 4;// 用户信息结果
}

/////////////////////////////////// 用户服务RPC定义 //////////////////////////////////
service UserService {
    // 检测昵称是否唯一
    rpc ValidNickname(ValidNicknameRequest) returns (ValidNicknameResponse);
    // 检测邮箱是否唯一
    rpc ValidEmail(ValidEmailRequest) returns (ValidEmailResponse);
    // 用户注册
    rpc UserRegister(UserRegisterRequest) returns (UserRegisterResponse);
    // 会话登录
    rpc SessionLogin(SessionLoginRequest) returns (SessionLoginResponse);
    // 密码登录
    rpc PasswdLogin(PasswdLoginRequest) returns (PasswdLoginResponse);
    // 获取验证码
    rpc GetCode(GetCodeRequest) returns (GetCodeResponse);
    // 邮箱验证码登录
    rpc VcodeLogin(VcodeLoginRequest) returns (VcodeLoginResponse);
    // 退出登录
    rpc Logout(LogoutRequest) returns (LogoutResponse);
    // 获取用户信息
    rpc GetUserInfo(GetUserInfoRequest) returns (GetUserInfoResponse);
}

```

### 3. 数据库设计

用户子服务中产生的数据将来存储在MySQL中，涉及到**用户表**和**会话表**。

#### 3.1. 用户表设计

用户表具体设计如下：
| 字段 | 类型 | 约束 | 空值 | 备注 |
| --- | --- | --- | --- | --- |
| id | BIGINT UNSIGNED | PRI | NOT NULL | 主键 |
| userId | varchar(32) | URI | NOT NULL | 必须唯一 |
| nickname | varchar(32) | URI | NOT NULL | 必须唯一 |
| email | varchar(255) | URI | NOT NULL | 必须唯一 |
| password | TEXT |  | NOT NULL | 存储加密后结果 |
| status | TINYINT |  | NOT NULL | 0：未登录，1：已登录 |

**注意**
- 密码必须存储加密后结果，不能存储明文密码。
- 系统支持用户昵称登录，因此用户昵称必须唯一。
- 系统支持用户邮箱登录，因此用户邮箱必须唯一。
- 创建用户表的SQL语句以及CURD操作将来由odb负责生成。

#### 3.2. 会话表设计

会话表具体设计如下：

| 字段 | 类型 | 约束 | 空值 | 备注 |
| --- | --- | --- | --- | --- |
| id | BIGINT UNSIGNED | PRI | NOT NULL | 主键 |
| sessionId | varchar(32) | URI | NOT NULL | 必须唯一 |
| userId | varchar(32) | | NOT NULL | |

**注意**
- 会话表中会话Id必须唯一
- 会话表中用户Id可以重复，因为chat2Data支持多设备登录相同账号，不同设备登录后对应不同的会话
- 创建会话表的SQL语句以及CURD操作将来由odb负责生成。

### 4. 缓存设计

缓存使用Redis，使用Cache-Aside(旁路缓存)策略：
- 写：写数据库，删除缓存，数据库是唯一"真数据源"
- 读：先查缓存，未命中时再查询数据库并回填缓存

#### 4.1. 个人信息缓存

过期时间：1小时
缓存策略：
- 写策略：写DB成功后，删除Redis。
- 读策略：先查redis，未命中再查DB，查到后回填Redis。
- 删除/失效策略：依赖TTL自然过期(因为chat2Data不支持用户注销，个人信息缓存自然过期即可)。
缓存类型：hash
key：user:userId
key：user:nickname:username
key：user:email:userEmail
value：
  - 用户id
  - 用户昵称
  - 用户密码
  - 用户邮箱
  - 用户状态

#### 4.2. 会话缓存

过期时间：3天
缓存策略：
- 写策略：先写DB，删除Redis
- 读策略：先查redis，未命中再查DB，查到后回填Redis(同样设置TTL为3天)。
- 删除策略：先删DB再删Redis，或者TTL到期后自动删除
缓存类型：hash
key：session:sessionId
value：
  - 会话Id
  - 用户Id

#### 4.3. 验证码缓存

过期时间：5min
缓存策略：
- 读策略：读Redis，用后即删(并没有物理删除，只是将其标记为不可用，物理删除依靠TTL)
- 删除策略：用后即删 或 TTL到期后自动删除
缓存类型：hash
key：verifyCode:codeId
value：
  - 验证码Id
  - 验证码
  - 用户邮箱
  - 验证码创建时间
  - 验证码是否使用：0：未使用，1：已使用


### 5. 实现流程

用户子服务实现流程如下：
1. 编写odb数据库表映射类，完成用户表和会话表的C++类映射，以及映射类的编译。
2. 封装odb生成操作mysql的C++代码，完成用户表和会话表的CURD操作，以及缓存读写操作。
3. 业务实现：
    - 封装会话管理类，完成创建会话、删除会话、检测会话有效性等
    - 用户业务类：完成用户注册、登录、获取用户信息等9个接口实现
4. RPC接口实现：完成用户子服务的RPC接口定义和实现
5. RPC服务器搭建：完成RPC服务器搭建，以及服务发现、服务注册、Redis、Etcd等初始化
6. 程序主流程实现：完成gflags参数解析、日志初始化、注册中心初始化、Redis初始化、以及RPC服务器启动
7. 编写完整CMakeLists.txt文件，完成用户子服务的整体编译
8. 在网关实现用户子服务的HTTP接口，配合前端代码测试用户子服务相关代码的正确性。
