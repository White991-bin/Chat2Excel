## 数据库驱动层

### 1. 数据库驱动层介绍

数据库驱动层为数据库子服务提供所有数据库操作支持。目前支持MySQL和SQLite数据库。包含以下模块：
- **SQL校验器**：主要规范化SQL、验证SQL语句的合法性、防止SQL注入、检测SQL的类型(只读SQL 或 修改类SQL)
- **基础结构定义**：提供基础的数据结构定义，包含数据库配置、列信息、表结构、参数绑定、查询结果集处理等
- **数据库驱动接口**：采用策略模式，定义数据库驱动的接口，包括连接数据库、断开数据库、执行SQL语句等方法
- **数据库驱动实现**：实现具体的数据库驱动，支持MySQL和SQLite数据库驱动
- **数据库驱动工厂**：使用工厂模式创建数据库驱动实例

### 2. 数据库驱动层设计

#### 2.1 SQL校验器

Chat2Data项目中，SQL语句一部分是数据库子服务自己提供，一部分来自AI子服务，AI子服务的SQL语句都是模型生成的。因此，数据库子服务在进行SQL操作前，需要校验SQL语句的合法性，安全性(主要是否存在SQL注入)，确保SQL语句安全后才能进行增删改查操作。
**SQL校验器需提供操作**
- 获取SQL语句类型
- 是否为只读类SQL
- 是否为修改类SQL
- 是否为有效表名
- 是否为有效列名
- 是否包含危险关键字
- 是否包含多条SQL语句
- 从SQL语句中提取涉及到的表名：要考虑各种CURD场景
- 移除SQL语句前后空白
- 移除SQL语句中注释
- 规范化SQL语句：移除SQL语句前后空白字符、注释等
- 是否为有效SQL语句：是否为支持的SQL类型、是否包含危险关键字、是否包含多条SQL语句等

**SQL类型枚举**
- **SELECT**：查询语句，用于从数据库中检索数据
- **SHOW**：显示数据库、表、索引等元数据
- **DESC**：显示表结构、索引等元数据
- **INSERT**：插入语句，用于将数据插入到数据库中
- **UPDATE**：更新语句，用于更新数据库中数据
- **DELETE**：删除语句，用于从数据库中删除数据
- **REPLACE**：替换语句，用于替换数据库中数据
- **TRUNCATE**：截空语句，用于截空数据库表
- **CREATE**：创建语句，用于创建数据库、表、索引等
- **DROP**：删除语句，用于删除数据库、表、索引等
- **ALTER**：修改语句，用于修改数据库、表、索引等
- **UNKNOWN**：未知语句，用于处理不支持的SQL语句

**危险关键字列表**
- **"DROP DATABASE"**：防止删除整个数据库
- **"DROP TABLE"**：防止删除整个表
- **"TRUNCATE"**：清空表数据
- **"DELETE FROM"**：删除表数据
- **"EXEC"**：执行系统命令
- **"EXECUTE"**：执行系统命令
- **"SCRIPT"**：执行脚本
- **"JAVASCRIPT"**：执行JavaScript
- **"EVAL"**：执行表达式
- **"UNION ALL SELECT"**：常见SQL注入模式
- **"1=1"**：常见SQL注入模式，比如攻击者输入：
- **"OR 1=1"**：SELECT * FROM users WHERE username = '' OR '1'='1'
- **" OR '1'='1'"**：SELECT * FROM users WHERE username = '' OR '1'='1'，会返回所有用户
- **"SLEEP("**：导致数据库响应延迟
- **"BENCHMARK("**：MySQL的性能测试函数，消耗CPU资源
- **"LOAD_FILE("**：读取文件内容
- **"INTO OUTFILE"**：将数据写入文件
- **"INTO DUMPFILE"**：将数据写入文件

**列名和表名规则**
- 不能为空
- 表名和列表包含：数字、字母、下划线、点、连接符(-)、中文
- 特殊名称需要使用引号包裹
- 表名和列表不能以数字开头
- 表名中包含分号、单双引号、空白字符、*、斜杠、反斜杠等则认为无效
- 不能多个连接符(-)、点(.)连续使用
- 数据库名包含：数字、字母、下划线、点、连接符(-)
- 不能超过数据库最大长度限制

**【注意】**
- 在进行SQL操作前，务必验证SQL的有效性、移除SQL注释、前后空白、无SQL注入风险，确保SQL语句安全后才能操作数据库
- 所有SQL语句必须是单条语句，禁止一行包含多条SQL语句。单条SQL语句必须以分号结尾。SQL中分号可能出现的两个地方：
  - 语句结束符：出现在SQL语句末尾，表示一条SQL语句结束
  - 字符串字面量：作为字符串数据的一部分 INSERT INTO messages (text) VALUES ('Hello; World');
  - 如果分号出现在字符串字面量内部，那么它不是语句分隔符，而是字符串数据的一部分。因此，分号是否出现在字符串字面量内部，就可以判断SQL语句是否包含多条语句

- 由于注释中可能存在一些恶意代码，因此需要将注释移除，移除注释时需要考虑各种注释格式，比如行注释(--)、多行注释(/*...*/)，字符串内的注释不移除


#### 2.2 基础结构定义
##### 2.2.1 数据库类型枚举
目前支持MySQL和SQLite数据库。定义枚举类型DBType，包含：MYSQL、SQLITE。

##### 2.2.2 数据库配置
以策略模式定义数据库连接配置抽象基类DBConfig，仅包含检测数据库配置是否合法抽象方法validConfig。
**MySQL数据库配置**
MySQL数据库的配置结构MySQLConfig，继承DBConfig，包含以下成员变量：
- 服务器地址、端口号、用户名、密码、数据库名称、字符集等
- 连接池配置
- 超时配置
- SSL配置
- 其他配置，以unordered_map组织
实现validConfig方法，检测MySQL数据库配置是否合法。

**SQLite数据库配置**
SQLite数据库的配置结构SQLiteConfig，继承DBConfig，包含以下成员变量：SQLite数据库文件路径
实现validConfig方法，检测SQLite数据库配置是否合法。

##### 2.2.3 列信息结构
列信息结构包括：
- 列名
- 列类型
- 是否为空(默认为true)
- 是否为主键(默认为false)
- 是否自动增长(默认为false)
- 默认值
- 最大长度(仅对字符串类型列有效)

##### 2.2.4 表信息结构
表信息结构包括：
- 表名
- 列信息集合
- 主键集合
- 索引集合
- 表注释

##### 2.2.5 sql操作结果结构
sql操作结果结构包括：
- 列名集合
- 列类型集合
- 行数据集合
- 影响行数
- 是否成功
- 错误信息

方法支持：
- 获取总列数
- 获取总行数
- 获取查询结果中指定行数据
- 获取操作是否成功
- 获取错误信息
- 将查询结果转换为JSON字符串
```json
{
  "success": "true",
  "error": "",
  "affectedRows": 10,
  "columns": [
    {"name":"id","type":"int"},
    {"name":"username","type":"varchar"}
  ],
  "rows": [
    [1,"admin"],
    [2,"user"]
  ]
}
```

##### 2.2.6 参数包装器
假设使用预编译语句执行SQL语句，在SQL语句预编译之后，需要将参数绑定到SQL语句中。
比如：
```sql
insert into student (name, age, score) values (?, ?, ?)
```
在执行SQL语句之前，需要将姓名、年龄、成绩等参数绑定到SQL语句中。为了一次性提供多个参数，需要将不同类型参数包装起来，使用统一的类型提供。

虽然参数类型繁多，但基本都可以转换为以下5种数据类型：
- **Null**
- **Int**
- **Double**
- **String**
- **Bool**

定义参数类型枚举ParamType，包含上述5种类型。

PreparedParam类对用户实际要绑定的数值，进行了统一包装，将不同类型参数转换为上述5种类型。
PreparedParam类：
**成员变量**
- 参数类型：根据用户实际要绑定的数值类型，自动选择ParamType中的类型。
- 整形值：默认值为0
- 浮点数值：默认值为0.0
- 字符串值：默认值为空字符串
- 布尔值：默认值为false

根据参数类型，将值填充到对应的成员变量中。

**成员方法**
- 支持各种类型数值构造，根据构造函数参数，填充数据类型以及数值
- 获取实际数据类型
- 检测是否为空值
- 获取各类型数值，类型完全匹配直接返回，类型不匹配尝试类型转换。不能转换返回默认值。

#### 2.3 数据库驱动接口
定义数据库操作的统一抽象接口，所有具体数据库驱动，都需要实现以下接口。接口如下：
- 连接数据库
- 断开数据库连接
- 测试连接(心跳检测)
- 执行查询类SQL
- 执行修改类SQL
- 执行预编译查询类SQL
- 执行预编译修改类SQL
- 开启事务
- 提交事务
- 回滚事务
- 转移字段名。数据库表名或字段名需要被'' 或 ""包裹，根据数据库类型选择合适的包裹符。

各个数据库驱动，根据自己的特性实现上述接口。

使用工厂模式，创建不同数据库驱动实例，支持动态注册新的数据库驱动。

#### 3.4 MySQL数据库驱动实现

MySQL数据库驱动在MySQLDatabase类中实现，头文件为mysqlDatabase.h、源文件为mysqlDatabase.cc。
成员变量：
- MySQL数据库配置
- MYSQL连接句柄
- 是否处于连接状态

ParamBinder(内部类)，用于预编译SQL语句的参数绑定
- 该类自己管理需要的存储空间，构造中根据SQL语句中参数个数，初始化MYSQL_BIND数组，每个元素初始化为0，并根据参数个数预分配整型缓冲区、浮点缓冲区、字符串缓冲区、字符串长度缓冲区和bool缓冲区，每个缓冲区的大小为参数个数，布尔缓冲区和空值缓冲区共享一块内存，bool缓冲区禁止使用std::vector<bool>，使用bool*。
- 根据参数在SQL语句中的索引，将PreparedParam对象值绑定对应对应索引的数据缓冲区，并将该索引数据缓冲区绑定到MYSQL_BIND数组对应索引的结构中
- 获取MYSQL_BIND绑定结果。
- 释放动态分配的内存空间。

ResultBinder(内部类)，用于绑定预编译语句结果集。
- 通过MYSQL_RES句柄获取结果集中字段个数，初始化MYSQL_BIND数组，并预分配各个类型字段缓冲区，建立MYSQL_BIND数组中各个元素和字段缓冲区的地址绑定，所有值统一以字符串方式绑定。
- 将MYSQL_BIND数组绑定到MYSQL_STMT中。
- 逐列获取结果集中的数据，最终保存在QueryResult中返回
- 根据MYSQL_RES句柄，获取结果集中字段信息，填充到QueryResult中。
- 释放动态分配的内存空间。

继承3.3中接口类，并实现所有接口。

#### 3.4 SQLite数据库驱动实现

SQLite数据库驱动在SQLiteDatabase类中实现，头文件为sqliteDatabase.h、源文件为sqliteDatabase.cc。请参考2.3中描述的抽象接口。
成员变量：
- SQLite数据库配置
- SQLite连接句柄
- 是否处于连接状态

ParamBinder(内部类)，用于预编译SQL语句的参数绑定
SQL语句中需要绑定的参数通过PreparedParams提供，PreparedParams是PreparedParam的容器，包含了SQL语句需要绑定的所有参数。根据PreparedParam中参数类型，将数值绑定到sqlite3_stmt中。

ResultReader(内部类)，用于读取预编译语句结果集。
- 将结果集中的列信息填充到QueryResult中
- 将结果集中的数据填充到QueryResult中

继承3.3中接口类，并实现所有接口。

#### 3.5 数据库驱动工厂

数据库工厂类在DatabaseFactory类中实现，头文件为databaseFactory.h、源文件为databaseFactory.cc。

- 支持不同数据库注册
- 根据数据库配置创建数据库
- 获取工厂实例(单例)
- 获取支持的数据库类型列表
- 检测某数据库是否支持
- 要注意线程安全
