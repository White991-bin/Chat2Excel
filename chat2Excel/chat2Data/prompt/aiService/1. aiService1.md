## AI子服务实现

### 1. AI子服务介绍

chat2Data项目支持以自然语言方式操作Excel文件 和 数据库，AI子服务主要负责和模型的交互，包括：
- 获取可用模型列表
- 新建聊天会话
- 获取聊天会话列表
- 获取指定用户指定聊天会话的历史消息
- 删除指定聊天会话
- 给模型发送消息(模型以流式响应)
- 关联聊天会话和文件

以上操作除关联聊天会话和文件，其他操作在ChatSDK中均有实现，AI子服务底层最终使用ChatSDK和模型进行交互。
AI子服务并不能独立完成所有功能，还需要其他服务配合：
- **用户子服务**：将来聊天消息可能要发送到用户邮箱，AI子服务需要通过用户子服务获取用户信息，从用户信息中拿到邮箱之后才能发送邮件。
- **文件子服务**：智能Excel场景中，在某个聊天会话中给模型发送消息，AI子服务收到发送消息请求后，需要通过文件子服务获取该聊天会话对应的Excel文件信息，以及worksheet对应的数据库表列表，这样AI子服务才知道要操作哪些数据库表。
- **数据库子服务**：在给模型发送消息时，AI子服务在拿到数据库表后，需要通过数据库子服务获取表结构以及表中的采样数据，这样模型才能根据表结构以及采样数据生成精准的SQL语句。AI子服务解析出模型生成的SQL语句之后，需要通过数据库子服务执行SQL语句。
- **邮件通知子服务**：用户若想将聊天内容发送到用户邮箱，AI子服务需要邮件通知子服务才能将聊天消息发送到用户邮箱。

除此之外，AI子服务还需要支持服务注册、服务发现等功能。因此AI子服务的主要职责是：
- 数据层：负责聊天会话数据的持久化存储和缓存操作
- 业务层：实现聊天会话管理，支持按用户隔离；封装ChatSDK，实现和模型交互逻辑
- 接口层：通过业务层提供的接口，实现RPC接口的具体逻辑
- 搭建RPC服务器，并进行服务注册和服务发现

### 2. ChatSDK

#### 2.1 ChatSDK介绍

ChatSDK是一款基于C++语言实现的大模型接入库，目前支持：
- 已接入DeepSeek-V4-flash、gpt-4o-mini、gemini-2.0-flash模型
- 支持Ollama本地接入deepseek-r1:1.5b模型
- 支持多轮聊天，全量消息和流式消息
- 支持会话管理：获取历史会话、获取历史会话消息
- 使用sqlite对会话数据进行持久化存储

AI子服务底层使用ChatSDK实现和模型的交互。

#### 2.2 ChatSDK数据管理

ChatSDK使用sqlite数据库对会话数据进行持久化存储，内部封装了聊天会话和聊天消息管理，主要涉及到聊天会话表和聊天消息表。

```sql

-- 聊天会话表
CREATE TABLE sessions (
    session_id TEXT PRIMARY KEY,  -- 会话Id
    model_name TEXT NOT NULL,     -- 模型名称
    create_time INTEGER NOT NULL, -- 会话创建时间
    update_time INTEGER NOT NULL  -- 会话更新时间
);
-- 消息表
CREATE TABLE messages (
    message_id TEXT PRIMARY KEY,  -- 消息Id
    session_id TEXT NOT NULL,     -- 会话Id
    role TEXT NOT NULL,           -- 角色类型：user 或 assistant
    content TEXT NOT NULL,        -- 消息内容
    timestamp INTEGER NOT NULL,   -- 消息时间戳
    FOREIGN KEY (session_id) REFERENCES sessions(session_id) ON DELETE CASCADE
);

```

#### 2.3 ChatSDK接口

ChatSDK向外提供了以下接口：
- 获取模型列表
- 新建聊天会话
- 获取聊天会话列表
- 获取指定聊天会话的历史消息
- 删除聊天会话
- 给模型发送消息(模型以流式响应)

### 4. 数据设计

#### 4.1 MySQL表设计
ChatSDK是一个通用的模型交互库，设计时并没有考虑将聊天会话按用户进行隔离。而Chat2Data项目支持不同的用户通过自然语言操作Excel或数据库，每次创建的聊天会话都需要和具体用户绑定，因此需要对ChatSDK中的聊天会话在上层进行扩展，以支持按照用户进行聊天会话隔离，即能通过用户Id筛选出当前用户所创建的所有聊天会话。所以在业务层需要重新设计聊天会话表，聊天会话表定义如下：
| 字段 | 类型 | 约束 | 空值 | 备注 |
| --- | --- | --- | --- | --- |
| id | BIGINT UNSIGNED | PRI | NO | 主键 |
| 聊天会话Id | VARCHAR(32) | UNI | NO | 和ChatSDK中的聊天会话Id保持一致 |
| 用户Id | VARCHAR(32) |  | NO | 支持会话按用户隔离 |
| 会话标题 | TEXT |  |  |  |
| 会话创建时间 | BIGINT |  | NO |  |
| 会话最近活跃时间 | BIGINT |  | NO | 每次新增加消息后更新最近活跃时间 |
| 消息总数 | INT |  | NO | 每次新增加消息后更新消息总数 |
| 模型名称 | TEXT |  | NO | 会话对应模型名称 |
| 文件Id | VARCHAR(32) |   |  | 会话关联的文件，打开历史会话消息时，需要预览Excel文件或连接SQLite数据库 |
| 会话类型 | VARCHAR(20) |  | NO | 会话类型: excel/database |
| 数据库连接信息 | TEXT |  |  | 会话关联的数据库连接信息，打开历史会话消息时，需要根据数据库连接信息连接数据库 |

当用户在前端页面点击某个历史会话消息列表时：
- 前端通过会话类型确认是excel场景还是数据库场景
- 如果是excel场景，前端会跳转到excel页面，发起excel文件预览，展示excel文件内容以及聊天消息
- 如果是数据库场景，前端会跳转到数据库页面，发起数据库连接，展示数据库表内容以及聊天消息

注意：
- excel文件删除后，该文件关联的聊天会话以及聊天消息都需要删除
- sqlite文件删除后，该文件关联的聊天会话以及聊天会话消息都需要删除，数据库连接信息也需要删除
- 聊天会话删除时，如果是excel场景，excel和会话映射表需要更新聊天会话Id为空；如果是数据库场景，无需处理数据库连接，因为点击了历史聊天会话列表后才有连接
- 将文件信息表的fileId作为聊天会话表的外键，并建立级联删除约束，确保当文件删除时，关联的聊天会话也会被删除
- 创建表的SQL语句，将来需要通过odb映射文件生成
- 数据库表名：tbl_chatSession

#### 4.2 缓存设计

过期时间：3天，与文件id保持一致
缓存策略：
- **写策略**：写DB成功后，删除Redis缓存中的数据，确保缓存和数据库数据一致
- **读策略**：Cache-Aside模式，先查Redis，命中则返回，未命中时再查MySQL，查到后回填Redis
- **删除/失效策略**：先删除MySQL，再删除Redis，或者TTL到期后自动删除

**缓存类型**：hash
**Key**： chat_session:sessionId
**Value**：
    - 聊天会话Id
    - 用户Id
    - 会话标题
    - 会话创建时间
    - 会话最近活跃时间
    - 消息总数
    - 模型名称
    - 关联文件Id
    - 会话类型
    - 数据库连接信息
    value最终会被组织成JSON结构进行缓存

#### 6.1 聊天会话管理

聊天会话管理是对ChatSessionData的进一步封装，实现对聊天会话的持久化存储、缓存以及数据库操作编排。
聊天会话元数据信息包含：
- 聊天会话Id(和ChatSDK中聊天会话Id一致)
- 用户Id
- 聊天会话标题(默认为第一条消息，最长20字)
- 聊天会话创建时间
- 聊天会话最近活跃时间
- 消息总数
- 使用模型名称
- 关联文件Id
- 会话类型
- 数据库连接信息(JSON字符串格式，主要是查看历史消息时，前端发起新建连接请求时需要)

聊天消息原信息包含：
- 消息Id(和ChatSDK中消息Id一致)
- 聊天会话Id(和ChatSDK中聊天会话Id一致)
- 角色(user/assistant)
- 消息内容
- 消息发送时间

聊天会话管理主要由类ChatSessionMgr实现，类中包含：
**成员变量**
- ChatSessionData实例指针：通过数据层实例进行持久化和缓存操作

**成员方法**
- 检测指定聊天会话是否属于指定用户
- 保存或更新聊天会话
- 通过用户Id获取用户所有聊天会话(从MySQL中获取，不从缓存获取，缓存中可能未包含该用户所有的聊天会话)
- 通过聊天会话Id获取指定聊天会话元数据
- 通过聊天会话Id删除指定聊天会话
- 将文件Id关联到聊天会话

#### 6.2 业务层实现

业务层在AIBusiness类中实现，该类是对ChatSDK聊天会话相关操作进行封装，并通过ChatSessionMgr实现对聊天会话管理，类中包含：
**成员变量**

- ChatSessionMgr实例指针：聊天会话管理实例，用于管理聊天会话的元数据和消息
- biterpc::SvcChannels实例指针：获取其他服务节点，进行RPC通信

**成员方法**
- 获取可用的模型列表
- 新建聊天会话
- 获取指定用户的聊天会话列表
- 通过聊天会话Id获取指定聊天会话元数据
- 获取指定用户指定聊天会话中所有历史消息
- 删除指定用户指定聊天会话
- 更新聊天会话关联的文件Id
